## Problem

In special education every student has an individualised education programme (IEP, "BEP" in Turkish): development area, long-term goal, short-term objective with a criterion such as 4 out of 5, and dated practice records under each objective. At this institution that chain lives in Word and Excel templates and on paper. Teachers enter the same information twice, and parents see little of it between meetings.

## Role

I work on it alone, from data model to screens. The client is a special-education institution.

## Architecture

The mobile app is feature-first: every feature has `data`, `domain` and `presentation` folders. State is Riverpod with code generation, entities are freezed classes with JSON serialisation, and navigation is go_router. There are two roles. Teachers get students, sessions, home-programme assignment, IEP progress entry and messages; parents get today's tasks, progress and messages.

Each feature talks to an abstract repository. Today the implementations are mocks fed from one demo dataset; one providers file per feature is where the real API gets swapped in.

The backend is a separate repository with three independent layers: Flutter → HTTP/JSON → NestJS → Prisma → PostgreSQL 16 in Docker. It has a health check, the Prisma connection and Swagger docs.

## Decisions

- Mock repositories behind interfaces instead of starting with the API, because I wanted the IEP model to settle on real screens before freezing a schema.
- NestJS instead of plain Express, because the student → IEP → goal → record hierarchy maps onto one module per level.
- Prisma instead of hand-written SQL, because migrations and typed queries are both generated from the one `schema.prisma` file.
- Docker Compose for PostgreSQL instead of a manual install, because the plan is to run the same file on the VPS.

## Outcome

In progress: the mobile repository has 44 commits and 123 Dart files, and both roles run end to end on demo data. Authentication and the core schema come next, then the mocks are replaced feature by feature. What I learned: once objectives and records had the right shape, the teacher and parent screens became two views of the same data.
